# Руководство по демонстрации Спринтов 6 и 7

Это руководство содержит пошаговую инструкцию по запуску, тестированию и валидации возможностей компилятора, реализованных в **Спринте 6 (Управляющие конструкции и Логика)** и **Спринте 7 (Массивы и Внешние функции)**.

Все тестовые файлы были упорядочены и распределены по поддиректориям в папке `examples/`.

## ✅ Чек-лист для успешной демонстрации

Для удобной сдачи проекта используйте следующий чек-лист:
- [ ] **Спринт 6:** Демонстрация вложенных `if-else` и циклов `while/for` (показать переходы и метки в asm).
- [ ] **Базовые IR Оптимизации:** Продемонстрировать работу **Constant Folding (CF)**, **Constant Propagation (CP)** и **Dead Code Elimination (DCE)**.
- [ ] **Продвинутые IR Оптимизации:** Устранение общих подвыражений **(CSE)**, распространение копий **(Copy Propagation)** и **Упрощение потока управления (Block Merging)**.
- [ ] **Оптимизации вызовов:** Демонстрация работы **Function Inlining** (встраивание простых/геттерных функций прямо в вызывающий код без инструкции `call`).
- [ ] **Оптимизации циклов:** Демонстрация **Loop Peeling (Unrolling 1-й итерации)**. Компилятор "разматывает" первую итерацию цикла `while` для возможности оптимизации и специализации стартового состояния.
- [ ] **Оптимизации памяти:** Демонстрация **Local & Global Dead Store Elimination (DSE)**. Компилятор математически доказывает, что запись в массив/указатель никогда больше не прочитается ни в одной из ветвей, и удаляет такие инструкции записи!
- [ ] **Локальные оптимизации (ASM):** Показать Peephole-окно (слияние флагов `setCC` и `jne`), а также **Strength Reduction** для деления/умножения/взятия остатка (замена `idiv` на битовые сдвиги `sar` / `and`).
- [ ] **Спринт 7:** Работа с массивами, генерация `lea` и битовых сдвигов `shl rax, 3` для вычисления адресов (без медленных `imul`).
- [ ] **Продвинутые Edge Cases:** Вызов функции с 8 аргументами (выгрузка аргументов >6 на стек в обратном порядке) и сохранение Caller/Callee-saved регистров.
- [x] **Внешние функции C:** Демонстрация вызова `printf` (форматный вывод), `scanf` (ввод), `malloc` (память на куче) и `free` (освобождение).
- [x] **Отладочная Информация (DWARF-маркеры):** Ассемблерный код теперь аннотируется метками `.loc`, маппящими машинные инструкции на исходный `.src` код (строка, колонка), что позволяет использовать пошаговую отладку в GDB.
- [x] **Встроенное профилирование:** Полностью автоматизирован сбор аппаратных метрик производительности и времени работы бинарников (через `perf` и `time`) с помощью единой команды CLI `run`.
- [x] **Пирамида тестирования:** Интегрирован **Fuzzing** (`tests/fuzz_tests.rs`) для проверки парсера на мусорных данных и **Differential Testing** (`scripts/differential_test.sh`) для автоматического сравнения вывода нашего компилятора с эталонным `GCC`.

## 🛠️ Спринт 6: Управляющие конструкции и Логика

Этот спринт включает поддержку ветвления (`if-else`), циклов (`while`, `for`), сложных логических условий (`&&`, `||`, `!`) с короткозамкнутым вычислением (short-circuit), а также генерацию соответствующего ассемблерного кода с метками и переходами.

### Демонстрационный пример 1: `sprint6_control.src`
Этот пример тестирует сложные условия, вложенные ветвления и циклы.

**Исходный файл:** `examples/sprint6/sprint6_control.src`

#### Шаг 1: Просмотр исходного кода
```c
fn main() -> int {
    int a = 10;
    int b = 20;
    int result = 0;

    // Сложные условия с short-circuit и ветвления
    if (a < b && b > 15) {
        result = 100;
    } else {
        result = -100;
    }

    // Цикл while с инкрементом
    int i = 0;
    while (i < 5) {
        result = result + i;
        i = i + 1;
    }

    return result;
}
```

#### Шаг 2: Компиляция в ассемблер (с оптимизацией)
Запустите команду компиляции:
```bash
cargo run -- compile --input examples/sprint6/sprint6_control.src --output examples/sprint6/sprint6_control.asm -O
```

#### Шаг 3: Что проверять в сгенерированном `.asm` файле?
Откройте файл `examples/sprint6/sprint6_control.asm` и обратите внимание на следующие важные моменты:
1. **Condition Code Fusion (Оптимизация переходов):**
   Вместо медленного вычисления флагов во временную переменную на стеке, оптимизатор склеил проверки. Сравнение `i < 5` скомпилировалось сразу в компактный условный переход:
   ```asm
   cmp rax, 5
   jl .while_body_2
   ```
2. **Инициализация переменных:**
   Переменные `a`, `b`, `result`, `i` инициализируются на стеке с правильным сдвигом (наш компилятор работает со стеком и 64-битными целыми, поэтому каждый слот занимает 8 байт).
3. **Логика условного перехода для `if-else`:**
   Внутри `.func_main` сгенерированы блоки для `.then_x` и `.else_x`, соединенные условными прыжками.

## 📦 Спринт 7: Массивы и Внешние функции C (ABI)

Этот спринт добавил поддержку выделения одномерных массивов на стеке, вычисления индексов с помощью инструкции `lea` (масштабирование на 8 байт для 64-битных целых), а также интеграцию со стандартной библиотекой C (`printf`, `scanf`, `malloc`, `free`) по стандарту **System V AMD64 ABI**.

### Демонстрационный пример 1: `sprint7_arrays.src`
Тестирует объявление, инициализацию элементов массива, чтение/запись по индексам.

**Исходный файл:** `examples/sprint7/sprint7_arrays.src`

#### Шаг 1: Просмотр исходного кода
```c
fn main() -> int {
    int arr[3];
    arr[0] = 5;
    arr[1] = 10;
    arr[2] = arr[0] + arr[1];
    
    return arr[2];
}
```

#### Шаг 2: Компиляция в ассемблер
```bash
cargo run -- compile --input examples/sprint7/sprint7_arrays.src --output examples/sprint7/sprint7_arrays.asm -O
```

#### Шаг 3: Что проверять в сгенерированном `.asm` файле?
1. **Аллокация стека:**
   Размер кадра стека увеличен (инструкция `sub rsp, 128` или больше) для резервирования места под 3 элемента массива (24 байта) плюс временные переменные.
2. **Адресная арифметика (`lea` + `shl`):**
   При записи в `arr[2]` компилятор вычисляет смещение. Обратите внимание на инструкции адресации:
   ```asm
   mov rax, 2            ; Индекс элемента
   shl rax, 3            ; Умножение индекса на 8 (размер int)
   ; ... вычисление адреса относительно RBP с помощью lea/add
   ```

### Демонстрационный пример 2: `test_extern.src` (Связь с C)
Тестирует вызовы внешних функций стандартной библиотеки C.

**Исходный файл:** `examples/sprint7/test_extern.src`

#### Шаг 1: Просмотр исходного кода
```c
fn main() -> void {
    printf("Testing external functions:\n");
    
    int ptr = malloc(40); // Выделяем 40 байт (5 x 8-байтных целых)
    printf("Allocated 40 bytes at address: %d\n", ptr);
    
    free(ptr);
    printf("Done!\n");
}
```

#### Шаг 2: Компиляция
```bash
cargo run -- compile --input examples/sprint7/test_extern.src --output examples/sprint7/test_extern.asm -O
```

#### Шаг 3: Анализ соответствия System V AMD64 ABI в ассемблере
Откройте сгенерированный ассемблер и найдите секцию перед вызовом `printf`:
1. **Выделение строковых литералов:**
   В самом конце или начале файла строки вынесены в секцию `.data` с автогенерируемыми метками:
   ```asm
   section .data
     str_lit_0: db "Testing external functions:", 10, 0
   ```
2. **Передача аргументов через регистры:**
   Первый аргумент (указатель на форматную строку) передается через `rdi`:
   ```asm
   mov rdi, str_lit_0
   ```
3. **Обнуление `al` для вариативных функций (Variadic Functions):**
   Перед `call printf` обязательно должна стоять очистка регистра `al` (так как мы не используем векторные/SSE регистры для передачи аргументов с плавающей точкой):
   ```asm
   xor eax, eax
   call printf
   ```
4. **Выравнивание стека по 16 байт:**
   Перед вызовом функций компилятор корректирует `RSP`, предотвращая падение Segmentation Fault в стандартной библиотеке C.

#### Шаг 4: Полный цикл сборки и запуска (для Linux / WSL)
Если вы находитесь в окружении Linux или WSL (Windows Subsystem for Linux), вы можете скомпилировать и запустить программу:
```bash
# 1. Транслируем в объектный файл ELF64
nasm -f elf64 examples/sprint7/test_extern.asm -o examples/sprint7/test_extern.o

# 2. Линкуем с библиотекой C (gcc автоматически подключит libc и настроит точку входа)
gcc examples/sprint7/test_extern.o -o examples/sprint7/test_extern -no-pie

# 3. Запуск!
./examples/sprint7/test_extern
```

**Ожидаемый вывод программы:**
```text
Testing external functions:
Allocated 40 bytes at address: <какой-то_адрес>
Done!
```

### 🧰 Доступные внешние C-функции

Наш компилятор автоматически линкует и поддерживает следующие функции из стандартной библиотеки (libc):
* `printf(format_str, ...)`: Поддерживает форматный вывод. Регистр `al` принудительно очищается `mov eax, 0` перед `call printf` (требование ABI для функций с переменным числом аргументов без float).
* `scanf(format_str, ...)`: Ввод данных с консоли.
* `malloc(size)`: Выделение динамической памяти в куче. Размер передается в `rdi`, указатель возвращается в `rax`.
* `free(ptr)`: Освобождение памяти.
* `exit(code)`: Мгновенное завершение программы.
* `print_int(x)` / `read_int()`: Наши кастомные обертки из `utils` (если необходимы).

## 🚀 Продвинутые сценарии (Edge Cases) и Оптимизации

Наш компилятор также тестирует и успешно обрабатывает сложные "пограничные" случаи (edge cases) при генерации кода:

1. **Тестирование сохранения регистров (Caller/Callee Saved)**
   - В функциях корректно реализовано сохранение **callee-saved** регистров (`rbx`, `r12`, `r13`, `r14`, `r15`). В прологе функции генерируются инструкции `push`, а перед инструкцией `ret` — строго симметричные инструкции `pop` в обратном порядке.
   - Это гарантирует, что вызывающая функция (caller) не потеряет свои данные в регистрах после вызова другой функции.
   - *Вы можете увидеть это в `complex_test.asm` в прологах/эпилогах `.func_do_nothing` и `.func_is_even`.*

2. **Функции с большим количеством аргументов (>6)**
   - Согласно System V AMD64 ABI, первые 6 целочисленных аргументов передаются через быстрые регистры (`rdi`, `rsi`, `rdx`, `rcx`, `r8`, `r9`).
   - Если аргументов больше 6 (например, **функция от 8 аргументов**), 7-й и 8-й аргументы корректно выгружаются в обратном порядке на стек перед инструкцией `call` и читаются оттуда вызываемой функцией через смещения `[rbp + 16]` и `[rbp + 24]`.

3. **Размер окна Peephole Оптимизатора**
   - Окно локального Peephole оптимизатора (peephole window) настроено на сканирование **5 инструкций (5 строк)**.
   - Например, для оптимизации `Condition Code Fusion` компилятор просматривает паттерн от `setCC al` до условного перехода `je/jne`, захватывая 5 строк:
     ```asm
     setl al             ; 1-я строка
     movzx rax, al       ; 2-я строка
     mov [rbp-16], rax   ; 3-я строка
     cmp rax, 0          ; 4-я строка
     jne .for_body       ; 5-я строка
     ```
   - Это 5-строчное окно "схлопывается" (fused) в одну сверхбыструю инструкцию `jl .for_body`.
