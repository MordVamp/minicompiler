# Итоговый отчет по разработке MiniCompiler (Спринты 5–8)

Этот документ содержит подробное описание ключевых функций, реализованных на финальных этапах разработки компилятора.

---

## 🚀 Спринты 5–6: Кодогенерация x86-64
На этом этапе компилятор научился превращать высокоуровневый код в настоящий машинный код.
*   **SSA (Single Static Assignment)**: Промежуточное представление (IR) переведено в SSA-форму, что позволило эффективно отслеживать жизненный цикл переменных.
*   **Управляющие конструкции**: Реализована генерация меток и переходов для `if-else`, `while` и `for`.
*   **Функции**: Реализована поддержка вызовов функций и возврата значений согласно **System V ABI** (использование регистров RDI, RSI, RDX и т.д. для передачи аргументов).

## 📦 Спринт 7: Массивы и Стандартная библиотека C
Расширение возможностей языка для работы с памятью.
*   **Массивы на стеке**: Реализована статическая аллокация массивов. Для доступа к элементам используется адресная арифметика (`lea` + `shl` для масштабирования индекса).
*   **Интеграция с libc**: Добавлена поддержка внешних функций `printf`, `scanf`, `malloc`, `free`. 
*   **Строковые литералы**: Реализован вынос текстовых строк в секцию `.data` ассемблера.

## ✨ Спринт 8: Оптимизации и Диагностика
Финальная полировка и демонстрация мощи компилятора.
*   **Продвинутые ошибки**: Реализован «красивый» вывод ошибок с указанием строки кода и маркером `^` на месте проблемы.
*   **Оптимизации**:
    *   *Constant Folding*: Вычисление выражений на этапе компиляции.
    *   *Constant Propagation*: Замена переменных их известными значениями.
    *   *Dead Code Elimination (DCE)*: Полное удаление кода, который не влияет на результат.
    *   *Peephole Optimizations*: Замена медленных команд (умножение на 2) на быстрые (сдвиг влево).
*   **Raytracer**: Написание сложной демо-программы, использующей математику и вложенные циклы.

В этом разделе объясняется "почему" и "как" работают реализованные механизмы.

### 1. SSA (Single Static Assignment) и IR
Промежуточное представление (IR) нашего компилятора построено на базе **SSA-формы**. 
*   **Суть**: Каждой переменной присваивается значение ровно один раз. Если переменная меняется в коде (`x = 1; x = 2;`), в IR создаются две разные версии: `x_1` и `x_2`.
*   **Преимущество**: Это превращает поток управления в направленный ациклический граф (DAG) внутри базовых блоков. Оптимизатору не нужно гадать, какое значение сейчас у `x` — он просто смотрит на номер версии. Это критично для *Constant Propagation* и *DCE*.

### 2. Вызов функций и System V ABI
Для того чтобы наш код мог вызывать функции из стандартной библиотеки C (например, `printf`), мы строго следуем стандарту **System V ABI** для x86-64:
*   **Регистры аргументов**: Первые 6 целочисленных аргументов передаются через `RDI, RSI, RDX, RCX, R8, R9`.
*   **Вариативные функции**: При вызове функций с переменным числом аргументов (как `printf`), регистр `AL` (младшая часть `RAX`) должен содержать количество используемых векторных регистров (в нашем случае всегда `0`).
*   **Выравнивание стека**: Перед вызовом функции стек (`RSP`) должен быть выровнен по 16-байтовой границе. Несоблюдение этого правила ведет к *Segmentation Fault* при вызове функций из `libc`.

### 3. Адресация массивов
Массивы в MiniCompiler — это непрерывные блоки памяти на стеке.
*   **Формула**: Адрес элемента `a[i]` вычисляется как `BaseAddress + i * ElementSize`.
*   **Оптимизация x86-64**: Мы используем инструкцию `lea` (Load Effective Address), которая позволяет процессору вычислить этот адрес за один такт. Например, `lea rax, [rbp - 40 + rcx*8]` вычисляет адрес 8-байтового элемента с индексом в `rcx`.

### 4. Алгоритмы оптимизации
*   **Constant Folding**: Выполняется на этапе обхода дерева (AST). Если узлы бинарной операции — константы, узел заменяется на результат. Это уменьшает объем IR еще до его генерации.
*   **Dead Code Elimination (DCE)**: Работает на основе SSA. Мы строим список всех "используемых" переменных (те, что идут в `Return`, `Store` или аргументы функций). Инструкции, результат которых не попал в этот список, считаются "мертвыми" и удаляются.
*   **Peephole Optimization**: Это финальный проход по готовому ассемблеру. Он ищет короткие паттерны (например, `mov rax, 0`) и заменяет их на более быстрые аналоги (`xor eax, eax`), которые короче в байтах и быстрее исполняются процессором.
