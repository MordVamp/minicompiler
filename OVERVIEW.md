# Техническое руководство по MiniCompiler

Этот документ содержит глубокий технический разбор архитектуры и реализации компилятора.

## 1. Лексический анализ (Lexer / Scanner)

Сканнер (`src/lexer/scanner.rs`) — это первый этап, который превращает сырой текст в поток структурированных токенов.

### Механика сканирования
*   **Управление состоянием**: Сканнер хранит `source` (ссылку на строку), `chars` (итератор символов) и переменные смещения: `start` (начало текущего токена) и `current` (текущая позиция байта).
*   **Поддержка UTF-8**: В отличие от простых сканеров на C, здесь используется `ch.len_utf8()` для корректного инкремента байтового смещения при работе с многобайтовыми символами.
*   **Lookahead (Заглядывание вперед)**:
    *   `peek()`: Позволяет проверить следующий символ без его поглощения.
    *   `r#match(expected)`: Проверяет символ и поглощает его только в случае совпадения (используется для `==`, `<=`, `+=` и т.д.).
    *   **Микро-транзакции**: Методы `save()` и `restore()` позволяют «откатить» состояние сканера. Это используется в `peek_token()`, чтобы заглянуть на целый токен вперед, не изменяя основной поток обработки.

### Особенности реализации
*   **Комментарии**: Поддерживаются однострочные (`//`) и многострочные (`/* ... */`) комментарии. Реализована поддержка **вложенных** блочных комментариев через счетчик `nesting`.
*   **Числа**: Различаются целые числа (`IntLiteral`) и числа с плавающей точкой (`FloatLiteral`). Сканнер проверяет валидность формата (например, `.5` или `10.` считаются ошибками в текущей спецификации).
*   **Ключевые слова**: Используется `HashMap` для быстрого сопоставления идентификаторов с зарезервированными словами (`if`, `fn`, `while` и т.д.).

## 2. Синтаксический анализ (Parser)

Парсер (`src/parser/parser.rs`) реализует алгоритм **рекурсивного спуска** (Recursive Descent) для грамматики типа LL(1).

### Иерархия выражений (Operator Precedence)
Парсинг выражений построен в виде «лестницы» методов от самого низкого приоритета к самому высокому. Это автоматически обеспечивает правильный порядок операций (умножение перед сложением):
1.  `parse_expression` (точка входа)
2.  `parse_assignment` (операторы `=`, `+=` — **правоассоциативны**)
3.  `parse_logical_or` (`||`)
4.  `parse_logical_and` (`&&`)
5.  `parse_equality` (`==`, `!=`)
6.  `parse_relational` (`<`, `>`, `<=`, `>=`)
7.  `parse_additive` (`+`, `-`)
8.  `parse_multiplicative` (`*`, `/`, `%`)
9.  `parse_unary` (`!`, `-`)
10. `parse_primary` (литералы, идентификаторы, вызовы функций и выражения в скобках)

### Вспомогательные методы (Helper Methods)
*   **`match_token(types)`**: Если следующий токен совпадает с одним из переданных типов, поглощает его и возвращает true.
*   **`consume(type, message)`**: Ожидает токен конкретного типа. Если его нет — выбрасывает ошибку (панику или `Result::Err`) с указанием места в коде.
*   **`check(type)`**: Просто проверяет тип текущего токена без продвижения вперед.

## 3. Абстрактное синтаксическое дерево (AST)

AST (`src/parser/ast.rs`) — это структура данных, представляющая логическую структуру программы.

### Представление в Rust
Используются перечисления (`enum`) для реализации полиморфизма:
*   **`DeclarationNode`**: Объявление функций (`fn`), структур (`struct`) или переменных.
*   **`StatementNode`**: Инструкции, которые не возвращают значение: блоки `{...}`, циклы `while`/`for`, условия `if`, `return`.
*   **`ExpressionNode`**: Все, что вычисляется в значение: литералы, операции, вызовы функций.

**Рекурсия в структурах**: Поскольку размеры перечислений должны быть известны при компиляции, рекурсивные связи (например, левая и правая части бинарной операции) оборачиваются в `Box<T>`.

### Визуализация (Formatting)
Для отладки и проверки тестов реализован метод `to_pretty_string()`. Он использует вспомогательную функцию `op_to_str` для преобразования внутренних типов токенов обратно в символы (`PLUS` -> `+`, и т.д.).

## 4. Система тестирования

### Юнит-тесты
Расположены внутри файлов `src/lexer/mod.rs` и `src/parser/mod.rs`. Проверяют мелкую логику: обработку конкретных символов или приоритетность операций.

### Золотые тесты (Golden Testing)
Файл `tests/test_runner.rs` реализует автоматизацию проверок на реальных файлах:
1.  Сканирует папку `tests/lexer/valid/` и `invalid/`.
2.  Для каждого файла `.src` ищет соответствующий файл `.txt`.
3.  Запускает компилятор, получает результат и сравнивает его с текстом в `.txt`.
4.  **UPDATE_EXPECT**: Если вы изменили формат вывода лексера, вы можете запустить:
    ```powershell
    $env:UPDATE_EXPECT="1"; cargo test
    ```
    Это автоматически перезапишет все `.txt` файлы новыми актуальными результатами, что избавляет от ручного обновления тестов.

## 5. Обработка ошибок

*   **Лексические ошибки**: Возвращаются в виде токена с типом `TokenType::Error`. Это позволяет сканеру не останавливаться на первом же плохом символе, а просканировать файл до конца.
*   **Синтаксические ошибки**: Возвращаются через `Result<T, String>`. При обнаружении ошибки парсер останавливается и передает сообщение с указанием строки и колонки.
